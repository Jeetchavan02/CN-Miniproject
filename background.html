Architectural Evolution

Protocol Evolution & Transport Architecture

From multiple uncoordinated TCP sockets to stream multiplexing, and finally to modern UDP-based QUIC.

1997 - RFC 2616

HTTP/1.1 (Persistent TCP)

Introduced keep-alive connections to reuse TCP sockets, but requests had to be processed sequentially (FIFO). Suffered severely from HTTP head-of-line blocking and domain sharding hacks.

2015 - RFC 7540

HTTP/2 (Binary Multiplexing)

Replaced plain text with binary framing, stream multiplexing over a single TCP connection, and HPACK header compression. Solved HTTP HoL, but inherited transport-layer TCP HoL blocking.

2022 - RFC 9000 / 9114

HTTP/3 & QUIC (UDP Native)

Moves transport from OS kernel TCP to encrypted UDP in user-space. Native independent streams, combined TLS 1.3 cryptographic handshake (1-RTT / 0-RTT), and connection migration via 64-bit Connection IDs.

Core Concepts

Frequently Asked Questions

Technical details regarding QUIC, transport protocol design, and zero round-trip handshakes.

QUIC (Quick UDP Internet Connections) is a modern transport layer network protocol designed initially by Jim Roskind at Google in 2012 and formally standardized by the IETF in RFC 9000 (May 2021). It replaces the combination of TCP and TLS by implementing encryption, congestion control, flow control, and stream multiplexing directly on top of UDP in user-space.
The public internet suffers from "protocol ossification": middleboxes (firewalls, NAT gateways, stateful routers) across ISPs drop any IP protocol numbers other than 6 (TCP) and 17 (UDP). Creating a new transport protocol (like SCTP) would cause up to 30-50% connection drop rates globally. By encapsulating traffic in UDP packets, QUIC traverses existing internet infrastructure seamlessly without requiring hardware firmware upgrades across millions of routers.
0-RTT (Zero Round-Trip Time) allows a returning client to transmit encrypted application data (like an HTTP GET request) inside the very first packet sent to the server. It utilizes cryptographic session tickets and pre-shared keys (PSK) cached from a previous TLS 1.3 handshake. While 0-RTT is vulnerable to replay attacks, QUIC servers mitigate this by restricting 0-RTT strictly to idempotent requests or implementing short anti-replay server timestamps.
TCP identifies connections by a 4-tuple: (Source IP, Source Port, Dest IP, Dest Port). When a mobile device switches from Wi-Fi to 4G/5G, its IP changes, forcibly terminating the TCP socket and requiring full renegotiation. QUIC uses a 64-bit Connection ID (CID) independent of IP and port numbers. Even if the client's network interface switches, the CID remains valid, allowing active video streams or downloads to continue uninterrupted.
